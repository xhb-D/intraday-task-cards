## 1. 产品目标

把“日内交易状态卡”和“Trading Risk Manager”整合为一个浏览器工具，使用户在同一个公开网址中完成：

1. 查看账户风险结论；
2. 维护 GC、CL、ES 日内交易状态；
3. 进入完整风险管理功能并返回首页；
4. 用一份完整 JSON 备份和恢复全部本地数据；
5. 使用当前统一 JSON 恢复完整数据，并继续兼容风险管理器独立备份。

该产品是手动记录与风险约束工具，不是行情、信号或订单系统。

## 2. 用户与主要场景

唯一目标用户为本机浏览器使用者。

### 2.1 日常使用

1. 打开首页；
2. 查看当前账户是否允许交易及下一单最大允许 1R；
3. 更新或撤销已实现余额；
4. 手动更新 GC、CL、ES 的偏见、交易方向、市场结构、机会和状态；
5. 必要时进入完整风险管理页面进行账户、时段和风险设置管理；
6. 返回首页后继续使用，数据不得重新加载或丢失。

### 2.2 备份与恢复

- 默认完整导出：一份 JSON，包含状态卡、风险管理器和外观偏好。
- 分项导出：风险管理器 JSON、现有 Markdown。
- 完整导入：同时替换两个数据域和外观偏好。
- 风险管理器独立导入：只替换风险域，状态卡与外观保持不变。
- 旧版独立日内状态卡 JSON：明确拒绝；当前内存、界面和 localStorage 均不得变化。
- 任何导入都必须先预览影响范围并由用户确认。

### 2.3 合并前数据迁移

- 公开站点首次启动时，如没有统一存档，只读取同一站点 origin 下的旧风险与外观键。
- 旧风险数据可迁移、校验并写入新的统一存档；旧独立状态卡键不读取、不迁移。
- 旧风险与外观键不得删除或覆盖。
- 已存在统一存档时，不得自动再次吸收旧键。

## 3. MVP 功能范围

### 3.1 单入口与内部导航

- 唯一入口为仓库根目录 `index.html`。
- 首页路由为 `#/home`，完整风险管理路由为 `#/risk`。
- 页面内提供明确的“进入 Trading Risk Manager”和“返回日内交易状态卡”入口。
- 浏览器返回、前进和硬刷新后应保持正确视图。

### 3.2 首页

- 顶部展示当前选中账户的风险结论、下一单最大允许 1R 和日初 Base R。
- 展示账户横向列表、添加账户、更新余额、撤销上一条余额更新、编辑账户。
- 账户数量增加时保留滚动、查看全部和移动端选择器。
- 下方保持 GC → CL → ES 三张状态卡及其当前已验收交互。

### 3.3 完整风险管理视图

- 保留现有账户 CRUD、余额历史、撤销、手动时段切换、Hard Loss Floor 和风险决策逻辑。
- 保留现有风险规则、状态、金额精度和生效时机。
- 不因视图切换重置活动表单以外的业务状态。

### 3.4 外观

- 全站统一支持跟随系统、浅色、深色。
- 两个视图使用同一选择值和视觉变量。
- 完整备份包含外观偏好。
- 导入风险管理器独立备份不改变外观。

## 4. 不得改变的业务规则

### 4.1 状态卡

- GC、CL、ES 相互隔离。
- 用户可见字段顺序为：当前偏见 → 交易方向 → 市场结构 → 当前机会 → 当前状态；卡片右上角 `3M` 徽标说明市场结构周期。
- 内部字段 `structure3m`、`structure3mAtRegistration` 保持不改名；`unjudged` / 未判断仅作当前统一数据的内部安全未选择态，不向用户提供按钮。
- 方向只受偏见约束：偏多为“只找多/暂无”，偏空为“只找空/暂无”，无偏见允许三种方向。结构不得反向清除合法方向。
- 机会只由方向与结构共同约束：顺向趋势允许“趋势回调、区间反转”，逆向趋势允许“区间反转、趋势反转”，震荡仅允许“区间反转”；无方向或未选择结构时全部禁用。
- 未入场机会遇结构变化导致机会非法时须确认后失效，方向保留；偏见变化导致方向冲突时须确认后失效并重置方向。持仓冲突只警示、不自动退出；偏见冲突在平仓后强制重选方向。
- 本次规则修订不改当前统一 schema 或字段名；当前统一 JSON 可继续导入，不对旧独立日内 JSON 迁移或猜测。
- “等待”和“找信号”为仅有的未入场注意力状态。
- 关键位置、登记快照、入场、平仓、删除不复活和多标签页写入锁规则保持不变。
- 市场结构字段名不显示周期；卡片右上角 `3M` 周期标记与内部 `structure3m` 逻辑保持不变。

### 4.2 风险管理器

- `LowR = HardLossAmount × 5%`，`MidR = 7.5%`，`HighR = 10%`。
- Base R、3R 预算、Profit Lock、有效保护线、Final Risk、BLOCKED 和配置生效时机全部遵循现有锁定规范。
- 仅使用已实现余额；不读取浮盈浮亏。
- 时段只允许用户手动切换，不按时钟自动重置。
- 风险输出是最大合法亏损上限，不是交易建议。

## 5. 数据与隐私规则

- 不向服务器上传用户数据。
- 不把真实账户名、余额或备份提交到 Git。
- 数据只存在于浏览器本地和用户主动下载的文件。
- 新统一存档是唯一写入源；旧风险存储只作受限迁移来源，旧独立日内状态卡存储不再参与恢复。
- 备份格式识别不得依赖文件名。
- 损坏或不支持的数据必须保留原始内容并进入恢复保护状态，不得用空白数据覆盖。

## 6. 失败处理

- 存储不可用：页面仍可使用内存状态并允许导出，明确提示尚未保存。
- 导入失败：当前内存、界面和本地存档均不改变。
- 回读不一致或其他标签页写入：锁定所有修改与危险恢复操作，导出仍可用。
- 旧风险存储损坏：不得自动生成统一存档；显示风险域诊断和恢复选择。
- 新旧存档同时存在且内容可能分叉：统一存档优先，不自动覆盖。

## 7. 非目标

- 不接入 TradingView、Tradovate、券商 API 或实时行情。
- 不下单、不自动产生交易信号、不自动改变方向。
- 不提供登录、云同步、多用户、跨设备同步或后台服务。
- 不修改风险算法；状态卡仅实施本规范冻结的约束矩阵与展示顺序，不全面重写状态机。
- 不在本次合并中决定或添加公开许可证。

## 8. 业务验收标准

1. 用户从一个网址完成首页和完整风险管理操作。
2. 两个视图使用同一份业务状态，切换和刷新后保持一致。
3. 当前统一备份与风险管理器独立备份按兼容规范导入，无业务数据丢失。
4. 旧独立状态卡备份被拒绝且零副作用；导入旧风险备份不会改变状态卡数据。
5. 完整导出 → 清空测试环境 → 导入后，两个数据域、外观和界面选择恢复。
6. 现有状态卡与风险管理器全部回归测试继续通过。
7. 本地验证不替代公开 GitHub Pages 验收。
