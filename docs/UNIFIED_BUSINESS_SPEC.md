# 统一交易控制中心 — Business Spec

- 状态：APPROVED / IMPLEMENTATION-AUTHORIZED
- 版本：2.0
- 日期：2026-09-28
- 决策路径：REUSE_COMPONENTS
- 修订：在既有 Vanilla JavaScript、纯函数状态模型、统一存档和风险管理器边界内，执行已授权的日内状态核心规则升级；风险管理器数据、公式和业务规则不变。

## 1. 产品目标

把“日内交易状态卡”和“Trading Risk Manager”整合为一个浏览器工具，使用户在同一个公开网址中完成：

1. 查看账户风险结论；
2. 维护 GC、CL、ES 日内交易状态；
3. 进入完整风险管理功能并返回首页；
4. 用一份完整 JSON 备份和恢复全部本地数据；
5. 使用当前统一 JSON 恢复完整数据，并继续兼容风险管理器独立备份。

该产品是手动记录与风险约束工具，不是行情、信号或订单系统。

## 2. 用户与主要场景

唯一目标用户为本机浏览器使用者。

### 2.1 日常使用

1. 打开首页；
2. 查看当前账户是否允许交易及下一单最大允许 1R；
3. 更新或撤销已实现余额；
4. 独立更新 GC、CL、ES 的偏见、市场结构、交易方向、机会和状态；
5. 选择机会时立即形成一条历史快照，不再填写或确认关键位置；
6. 必要时进入完整风险管理页面进行账户、时段和风险设置管理；
7. 返回首页后继续使用，数据不得重新加载或丢失。

### 2.2 备份与恢复

- 默认完整导出：一份 JSON，包含状态卡、风险管理器和外观偏好。
- 分项导出：风险管理器 JSON、现有 Markdown。
- 完整导入：同时替换两个数据域和外观偏好。
- 风险管理器独立导入：只替换风险域，状态卡与外观保持不变。
- 旧版独立日内状态卡 JSON：明确拒绝；当前内存、界面和 localStorage 均不得变化。
- 任何导入都必须先预览影响范围并由用户确认。

### 2.3 合并前数据迁移

- 公开站点首次启动时，如没有统一存档，只读取同一站点 origin 下的旧风险与外观键。
- 旧风险数据可迁移、校验并写入新的统一存档；旧独立状态卡键不读取、不迁移。
- 已存在统一存档时，不得自动再次吸收旧键。

## 3. MVP 功能范围

### 3.1 单入口与内部导航

- 唯一入口为仓库根目录 `index.html`。
- 首页路由为 `#/home`，完整风险管理路由为 `#/risk`。
- 页面内提供明确的“进入 Trading Risk Manager”和“返回日内交易状态卡”入口。
- 浏览器返回、前进和硬刷新后应保持正确视图。

### 3.2 首页

- 顶部展示当前选中账户的风险结论、下一单最大允许 1R 和日初 Base R。
- 展示账户横向列表、添加账户、更新余额、撤销上一条余额更新、编辑账户。
- 账户数量增加时保留滚动、查看全部和移动端选择器。
- 下方保持 GC → CL → ES 三张相互隔离的状态卡及其当前已验收交互。
- 每张卡的可见顺序固定为：当前偏见 → 市场结构 → 交易方向 → 当前机会 → 当前状态。

### 3.3 完整风险管理视图

- 保留现有账户 CRUD、余额历史、撤销、手动时段切换、Hard Loss Floor 和风险决策逻辑。
- 保留现有风险规则、状态、金额精度和生效时机。
- 不因视图切换重置活动表单以外的业务状态。

### 3.4 外观

- 全站统一支持跟随系统、浅色、深色。
- 两个视图使用同一选择值和视觉变量。
- 完整备份包含外观偏好。
- 导入风险管理器独立备份不改变外观。

## 4. 冻结业务规则

### 4.1 日内状态卡

#### 4.1.1 字段、顺序与标题

- GC、CL、ES 完全隔离；一个商品的变更不得改变其他商品的当前状态或历史。
- 当前偏见枚举仍为“偏多 / 无偏见 / 偏空”。
- 市场结构标题必须保留：`市场结构（比较20均线和波段高低点）`。
- 市场结构可见选项仍为多头、震荡（观察拍卖完成）、空头；内部 `unjudged` / 未判断仍是安全未选择态，不向用户提供按钮。
- 交易方向标题必须保留：`交易方向（市场结构不明确时看HTF缺口）`。
- 交易方向按钮文案固定为：`做多`、`做空`、`暂无交易方向`。
- 当前机会按钮文案固定为：`MTF PB`、`HTF PB`、`HTF BOF`。
- 当前状态仍显示无机会、等待、找信号、持仓。
- 可见顺序固定为：当前偏见 → 市场结构 → 交易方向 → 当前机会 → 当前状态。

#### 4.1.2 偏见与方向完全解耦

- 当前偏见不限制交易方向。
- 偏多、无偏见、偏空三种偏见下，均可选择做多、做空或暂无交易方向。
- 市场结构也不得反向清除或禁用合法交易方向。
- 交易方向为暂无交易方向时，不得选择当前机会；方向恢复为做多或做空后，才重新具备机会选择条件。

#### 4.1.3 机会选择

- 交易方向不是暂无交易方向且市场结构已经选择（不是 `unjudged`）时，MTF PB、HTF PB、HTF BOF 三种机会均可选择。
- 机会选择不再受偏见、交易方向或市场结构的组合矩阵限制。
- 同一个商品同时只能有一个当前机会。
- 重复选择当前相同机会无副作用，不重置 ID、登记时间、阶段时间或历史记录。
- 改选其他机会时，旧机会按既有取消语义结束，随后创建新机会；旧记录和新记录均保持可审计。
- 选择机会立即自动登记并写入历史，历史快照至少保留偏见、市场结构、交易方向、机会类型、机会 ID、登记时间、阶段时间和生命周期时间。
- 新机会不再以关键位置作为创建、登记、等待、找信号、入场或平仓条件。

#### 4.1.4 位置提示与状态摘要

- 删除整行“关键位置”输入框、确认按钮和相关提示。
- 原位置区域改为只读提示，文字必须为：`入场信号：原方向拒绝+新方向位移（COC）+价格接受（震荡）`。
- 当前状态摘要使用新交易方向和新机会名称，不显示关键位置。
- 历史界面可以保留旧记录的关键位置列：旧记录显示原值；新记录显示 `—`。新记录不要求关键位置字段有值。

### 4.2 机会生命周期与历史

- 新机会默认进入等待；等待与找信号可以直接双向切换。
- 等待、找信号均可在确认实际成交后进入持仓；系统只记录事实，不发送订单。
- 持仓只能通过确认全部平仓结束；部分减仓不视为平仓。
- 删除历史记录不改变当前机会、持仓或其他商品，也不自动复活被删除记录。
- 方向改变导致未入场机会结束时，沿用既有“方向改变结束”原因；偏见或市场结构改变不再因矩阵冲突自动结束新机会。

### 4.3 历史数据与升级迁移

- 日内状态数据版本从 V3 升级到 V4。
- 旧历史记录必须保留旧机会名称、关键位置、时间线和原始业务含义，不得把旧机会类型静默改名为 MTF PB、HTF PB 或 HTF BOF。
- V3 统一存档中的旧活动机会必须确定性、安全结束，并写入可审计的规则升级原因；迁移后不得继续作为当前活动机会。
- 旧活动机会无论仍在等待/找信号还是已经持仓，均以“规则升级结束”安全结束；持仓机会必须保留原 `enteredAt` 与完整 `wait → position` 时间线，仅结束最后阶段。该迁移结果不改变普通“已平仓”与其他结束原因的严格语义。
- 已有旧活动记录保留其旧机会类型和关键位置，并以“规则升级结束”结束；未曾写入历史的旧活动机会至少进入日内迁移审计记录，保留商品、旧机会类型、旧关键位置（如有）、原 ID、原阶段和结束时间。
- 迁移时间必须确定性计算：取统一日内 envelope 的 `savedAt` 与旧机会/记录时间线中合法时间戳的最大值。
- 损坏、未知或无法安全校验的版本必须 fail-closed，保留原始内容，不得静默生成空白或覆盖 canonical 存档。

### 4.4 风险管理器

- `LowR = HardLossAmount × 5%`，`MidR = 7.5%`，`HighR = 10%`。
- Base R、3R 预算、Profit Lock、有效保护线、Final Risk、BLOCKED 和配置生效时机全部遵循现有锁定规范。
- 仅使用已实现余额；不读取浮盈浮亏。
- 时段只允许用户手动切换，不按时钟自动重置。
- 风险输出是最大合法亏损上限，不是交易建议。
- 本次升级不修改风险管理器的数据、公式、迁移器、导入导出语义或业务规则。

## 5. 数据与隐私规则

- 不向服务器上传用户数据。
- 不把真实账户名、余额或备份提交到 Git。
- 数据只存在于浏览器本地和用户主动下载的文件。
- 新统一存档是唯一写入源；旧风险存储只作受限迁移来源，旧独立日内状态卡存储不再参与恢复。
- 备份格式识别不得依赖文件名。
- 损坏或不支持的数据必须保留原始内容并进入恢复保护状态，不得用空白数据覆盖。
- 日内 V4 新记录允许关键位置为空/缺省；旧记录的关键位置必须按原值保留。

## 6. 失败处理

- 存储不可用：页面仍可使用内存状态并允许导出，明确提示尚未保存。
- 导入失败：当前内存、界面和本地存档均不改变。
- V3 统一存档迁移失败：进入恢复保护，保留原始统一 JSON；不得部分写入迁移结果。
- 回读不一致或其他标签页写入：锁定所有修改与危险恢复操作，导出仍可用。
- 旧风险存储损坏：不得自动生成统一存档；显示风险域诊断和恢复选择。
- 新旧存档同时存在且内容可能分叉：统一存档优先，不自动覆盖。

## 7. 非目标

- 不接入 TradingView、Tradovate、券商 API 或实时行情。
- 不下单、不自动产生交易信号、不自动改变方向。
- 不提供登录、云同步、多用户、跨设备同步或后台服务。
- 不引入第三方状态机、规则引擎或其他运行时依赖。
- 不改变风险管理器的数据、公式和业务规则。
- 不在本次合并中决定或添加公开许可证。

## 8. 业务验收标准

1. 三种偏见分别都允许选择做多、做空和暂无交易方向。
2. 每种已选择的市场结构与做多/做空组合下，MTF PB、HTF PB、HTF BOF 均可选择。
3. 同一商品只能有一个当前机会；同机会重复选择无副作用，切换机会结束旧记录并登记新记录。
4. 选择机会立即生成历史记录，并保存偏见、结构、方向、机会类型和时间快照。
5. 新机会不需要关键位置即可等待、找信号、入场和平仓；原位置区域只显示冻结提示。
6. V3 当前统一数据能够安全、确定性迁移到 V4；旧历史名称和关键位置不被改写。
7. 旧活动机会迁移结果确定、已结束且有可验证升级原因。
8. GC、CL、ES 隔离不变；风险管理器和统一导入导出回归通过。
9. 页面点击后保持滚动位置的既有功能不回退。
10. 生产 `dist/app.bundle.js` 已更新，`npm test` 与 `npm run build` 通过并报告实际数量。
11. 完整 diff 无无关修改；本地预览可打开并提供给用户验收。
