# 日内交易实时状态卡 V1

本地、无网络的桌面浏览器工具，用于保持 GC、CL、ES 的日内交易任务状态。界面字段标题为“市场结构（比较20均线和波段高低点）”，其 3M 周期由卡片右上角的 `3M` 徽标说明。它不读取行情、不连接 TradingView 或券商，也不发送订单。

## 打开

方式 1（适合日常使用）：直接双击 `index.html`。页面加载仓库内已生成的 `dist/app.bundle.js`，不依赖 ES Module、CDN、网络或运行时服务器。

方式 2（需要更稳定持久化时推荐）：在本目录运行 `npx serve .`，再打开显示的 `http://localhost:xxxx` 地址。

Safari 的 `file://` 本地文件模式是否允许 localStorage 由浏览器策略决定：即使不可用，三张卡和内存状态仍可正常使用，页面会显示“尚未保存”降级提示，Markdown / JSON 导出仍可用。长期保存请使用 localhost 模式或定期导出 JSON。迁移或清理浏览器数据前请导出 JSON。

开发者修改 `src/` 后运行 `npm run build` 更新已提交的 `dist/app.bundle.js`；最终用户不需要运行构建命令。

## 结构

- `src/model.js`：纯业务状态机、机会/记录 identity 和不变量。
- `src/persistence.js`：当前 V3 section envelope 的结构校验、序列化和 Markdown 导出。
- `src/startup.js`：存储故障隔离；保证先创建内存工作区，再尝试恢复。
- `src/app.js`：DOM 渲染、确认对话框和浏览器 I/O。
- `dist/app.bundle.js`：供直接双击 `index.html` 使用的 classic-script 生产 bundle。
- `styles.css` 与 `refinement.css`：固定 GC / CL / ES 三卡桌面优先界面与信息层级微调。
- `test/model.test.js` 与 `test/revision.test.js`：验收场景、结构门控与随机不变量测试。

## 偏见、市场结构与交易方向

每张卡独立维护三个不同的手动字段，用户可见顺序为“当前偏见 → 市场结构 → 交易方向 → 当前机会 → 当前状态”；卡片右上角 `3M` 徽标说明市场结构的执行周期：

- **当前偏见**：偏多 / 无偏见 / 偏空。它约束交易方向；持仓期间仍可更新，但不会自动平仓。
- **市场结构（比较20均线和波段高低点）**：多头 / 震荡 / 空头。它只约束当前机会；当前统一 JSON 中的 `unjudged` / 未判断保留为内部安全未选择态，不作为可点击选项。
- **交易方向（市场结构不明确时看HTF缺口）**（未持仓时）：只找多 / 只找空 / 暂无交易方向。它只受当前偏见约束，不由市场结构反向决定。

偏见与交易方向矩阵：

| 当前偏见 | 可选交易方向 |
| --- | --- |
| 偏多 | 只找多、暂无交易方向 |
| 无偏见 | 只找多、只找空、暂无交易方向 |
| 偏空 | 只找空、暂无交易方向 |

机会由交易方向和市场结构共同约束：多头/空头顺向允许“趋势回调、区间反转”，逆向允许“区间反转、趋势反转”，震荡只允许“区间反转”。暂无方向或内部未选择结构时，所有机会禁用。“趋势反转”名称保持不变。

未入场的活跃机会如因结构变更而不再兼容，会先要求确认；确认后机会以“失效”结束，内部原因记录为 `structure_change`，交易方向保留。偏见变更若使方向冲突，未入场机会同样须确认；确认后以 `bias_change` 失效并重置方向。持仓期间的偏见或机会结构冲突只显示警示、不自动平仓；偏见冲突的持仓在确认平仓后强制重新选择方向。

## 数据与保存

每张卡保存偏见、市场结构、交易方向、当前机会和空闲状态起点。市场结构仍是内部 3M 逻辑。机会保存稳定 `id`、已确认位置 `zone`、未确认草稿 `zoneDraft`、登记/入场/结束时间、注意力阶段及阶段片段。首次登记会冻结 `biasAtRegistration` 与兼容字段 `structure3mAtRegistration` 快照；后续修改偏见、结构或重新确认位置都不会改写它们。历史记录是机会的无草稿快照；删除记录不会触碰当前机会，也不会自动复活。

注意力阶段固定为“等待 → 找信号”，可直接双向切换；建立新机会默认“等待”，两种状态都可确认入场，重复点击不会重置阶段计时。

当前唯一持久化键为 `trading-control-center:v1`。完整 JSON 备份包含状态卡、风险管理器与外观偏好；导入先校验、预览并二次确认。旧版独立日内状态卡 JSON（无论历史 schema）会被明确拒绝，且不改变内存状态或 localStorage；请使用当前统一交易控制中心 JSON。风险管理器的既有独立备份仍可作为只替换风险域的兼容输入。`unjudged` 仅作为当前统一数据中的内部安全态保留。

## 已知限制

- localStorage 受浏览器策略和容量限制；保存失败时页面会提示“尚未保存”，保留内存数据并允许导出 JSON。
- 损坏或 schema 不兼容的本地存档不会被空白状态覆盖。三张卡仍会显示；可导出原始存档、恢复有效备份，或经确认后开始空白工作区。
- 页面显示最后一次手动任务状态；恢复不重新核验行情或真实持仓。
